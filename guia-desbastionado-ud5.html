UD05 · Bastionado de servidores · Máster en Ciberseguridad U-TAD

Guía de desbastionado y bastionado

Dos scripts dejan las VMs de laboratorio deliberadamente inseguras para rebastionarlas en clase paso a paso. Para cada sistema: cómo ejecutar el script, y una tabla con la debilidad, cómo se explotaría y el comando que la corrige.

▲

Solo en el laboratorio aislado. Estos scripts debilitan la seguridad a propósito. Ejecútalos únicamente en las VMs del laboratorio, en red Host-Only y con una snapshot de instalación fresca.

Para volver al estado seguro entre pruebas: restaura la snapshot de la VM. No ejecutes nada de aquí en un equipo real ni en una red de producción.

El laboratorio

Kali Linux

Atacante. Lanza las demos de la columna «explotación»: nmap, hydra, nxc/netexec, hashcat/john, Metasploit.

Ubuntu Desktop

Víctima Linux. Script desbastionar-ubuntu.sh (bash). Demos de SSH, sudo/GTFOBins, permisos, telnet.

Windows Server 2019

Víctima Windows. Script Desbastionar-WindowsServer2019.ps1 (PowerShell). Demos de RDP, UAC, SMB, spraying.

Toma la IP de cada víctima con ip a (Ubuntu) o ipconfig (Windows) y úsala como HOST/IP en los comandos de ataque desde Kali.

Ubuntu Desktop bash · desbastionar-ubuntu.sh

Cómo ejecutar el script

# 1. Copia el script a la VM (o pégalo con nano) y dale permisos
chmod +x desbastionar-ubuntu.sh

# 2. Ejecútalo como root. Pedirá escribir DESBASTIONAR para confirmar
sudo ./desbastionar-ubuntu.sh

# Opciones:
#   -y        modo desatendido (sin confirmación)
#   --no-apt  no instalar paquetes (telnetd) si la VM no tiene internet
sudo ./desbastionar-ubuntu.sh -y --no-apt

# 3. Reinicia para que ASLR, AppArmor y servicios queden en su estado débil
sudo reboot

Copias de seguridad de los ficheros en /root/desbastionado-backups-<fecha> · registro en /var/log/desbastionado-ud5.log. Usuarios de demo que crea: root/toor y becario/123456.

Windows Server 2019 PowerShell · Desbastionar-WindowsServer2019.ps1

Cómo ejecutar el script

# 1. Abre PowerShell COMO ADMINISTRADOR

# 2. Permite ejecutar el script solo en esta sesión
Set-ExecutionPolicy -Scope Process Bypass -Force

# 3. Ejecútalo. Pedirá escribir DESBASTIONAR para confirmar
.\Desbastionar-WindowsServer2019.ps1

# Modo desatendido (sin confirmación):
.\Desbastionar-WindowsServer2019.ps1 -Force

# 4. Reinicia: UAC, Defender y SMBv1 necesitan reinicio
Restart-Computer
!

Windows Defender. Si la Protección contra manipulaciones (Tamper Protection) está activa, el comando no podrá apagar Defender: desactívala primero en «Seguridad de Windows → Protección antivirus y contra amenazas» y vuelve a ejecutar el script (o hazlo por GPO). El script avisa si no pudo.

Sobre EternalBlue (MS17-010)

El script reactiva SMBv1 para la parte defensiva (detectarlo y volver a deshabilitarlo). No es un RCE real en Windows Server 2019: el sistema está parcheado, así que nmap --script smb-vuln-ms17-010 saldrá «not vulnerable». En clase se muestra la detección con nmap y el comando defensivo (Get-WindowsOptionalFeature … SMB1Protocol), y se explica EternalBlue a nivel conceptual. Para verlo como RCE real haría falta un objetivo heredado (Windows 7 / Server 2008 R2 o Metasploitable3), que no está en este laboratorio.

Rutina de clase sugerida

1 · Desbastionar

Ejecuta el script en la VM víctima y reinicia. Parte de la snapshot fresca.

2 · Explotar

Desde Kali, lanza la columna «explotación» de una fila: la demostración funciona porque el control no está.

3 · Bastionar

Aplica el comando de la columna «bastionar» y repite el ataque: ahora falla. Es la slide 8 en directo.

4 · Restaurar

Entre bloques o grupos, restaura la snapshot fresca para partir del mismo estado.
